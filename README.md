# MessagePack first-deserialize memory repro (Unity IL2CPP)

The first `MessagePackSerializer.Deserialize<T>()` of a type handled by the source-generated resolver allocates
memory in proportion to **every** type the resolver knows, not just `T`. In this project, deserializing a 2-byte payload
into a one-field class allocates **11 MB** of native memory and initializes **5,755** IL2CPP classes, and 99% of that is the
generated resolver's first lookup.

- Unity 2022.3.57f1, IL2CPP
- MessagePack 3.1.12, installed as its README describes: `MessagePack` from NuGet through
  [NuGetForUnity](https://github.com/GlitchEnzo/NuGetForUnity) 4.5.0, plus the `MessagePack.Unity` git package at `#v3.1.12`

## Run it

Unity needs `git` to fetch the two git packages, and the IL2CPP module for the editor's platform (on Windows, also
Visual Studio's C++ build tools).

1. Open the project with Unity 2022.3.57f1.
2. Choose **Repro > Build IL2CPP Player**. This builds a standalone player for the editor's platform into `Build/`.
   **File > Build And Run** works too, because the project already uses IL2CPP and has the scene in its build list.
3. Run the player. The results appear on screen and in the player log (`Player.log`). Pass `-quitAfterProbe` to exit
   when it is done, for example:

   ```
   Build/StandaloneOSX/MessagePackIl2CppRepro.app/Contents/MacOS/MessagePackIl2CppRepro -batchmode -nographics -quitAfterProbe -logFile -
   ```

The numbers only mean something in an IL2CPP player. In the editor (Mono), the IL2CPP counters read 0.

## What it does

[`Assets/Scripts/FirstDeserializeProbe.cs`](Assets/Scripts/FirstDeserializeProbe.cs) runs once after the scene loads.
It takes a snapshot of the memory and IL2CPP counters before and after each of four calls:

1. `MessagePackSerializer.Deserialize<int>(new byte[] { 0x01 })`. This warms up the standard resolvers.
2. `GeneratedMessagePackResolver.Instance.GetFormatter<Ping>()`. [`Ping`](Assets/Scripts/Ping.cs) is a class with one
   `int` field. This is the lookup that `Deserialize<Ping>` reaches through `StandardResolver`, called directly to show
   how much of the first deserialization it accounts for.
3. `MessagePackSerializer.Deserialize<Ping>(new byte[] { 0x91, 0x01 })`. This is the rest of the first deserialization:
   the resolver chain before the generated resolver, and the formatter itself.
4. The same call again.

It also prints steps 2 and 3 combined, which is what the first `Deserialize<Ping>` costs.

[`Assets/Scripts/Messages.g.cs`](Assets/Scripts/Messages.g.cs) stands in for a game's message catalog: 600 classes,
60 structs and 80 enums, whose members use `List<T>`, `T[]`, `Dictionary<K, V>` and so on. The probe never uses these
types; they are only there because the source generator registers them. It was generated by
[`Tools/generate_messages.py`](Tools/generate_messages.py).

"Native memory" is `Profiler.GetTotalAllocatedMemoryLong()`; IL2CPP allocates its runtime metadata through Unity's
memory manager, so it is included. The IL2CPP columns come from `il2cpp_stats_get_value`.

## Results

macOS 27 standalone player on Apple silicon; the numbers were identical in every run:

| Step | Native memory | Managed heap | Classes initialized | Methods | Generic classes | Inflated methods |
|---|---:|---:|---:|---:|---:|---:|
| 1. `Deserialize<int>`, warm-up | 1,364 KB | 204 KB | 398 | 1,501 | 799 | 2,765 |
| 2. `GeneratedMessagePackResolver.Instance.GetFormatter<Ping>()` | **11,013 KB** | 220 KB | **5,731** | 20,867 | 5,025 | 25,936 |
| 3. `Deserialize<Ping>` #1 | 64 KB | 4 KB | 24 | 44 | 39 | 93 |
| 4. `Deserialize<Ping>` #2 | 0 | 0 | 0 | 0 | 0 | 0 |
| First use of `Ping` (2 + 3) | 11,077 KB | 224 KB | 5,755 | 20,911 | 5,064 | 26,029 |

## Why

The source generator emits one resolver per assembly. For this project, MessagePack 3.1.12 generates this helper
(excerpt; the full file has 2,139 entries in each list):

```csharp
private static class GeneratedMessagePackResolverGetFormatterHelper
{
    private static readonly global::System.Collections.Generic.Dictionary<global::System.Type, int> closedTypeLookup = new global::System.Collections.Generic.Dictionary<global::System.Type, int>(2139)
    {
        { typeof(global::Repro.Messages.Msg0101[]), 0 },
        // ...
        { typeof(global::System.Collections.Generic.List<global::Repro.Messages.Msg0100>), 897 },
        // ...
        { typeof(global::Repro.Messages.Msg0000), 1479 },
        // ...
    };

    internal static object GetFormatter(global::System.Type t)
    {
        if (closedTypeLookup.TryGetValue(t, out int closedKey))
        {
            switch (closedKey)
            {
                case 0: return new MsgPack::Formatters.ArrayFormatter<global::Repro.Messages.Msg0101>();
                // ...
                case 897: return new MsgPack::Formatters.ListFormatter<global::Repro.Messages.Msg0100>();
                // ...
                case 1479: return new global::MessagePack.GeneratedMessagePackResolver.Repro.Messages.Msg0000Formatter();
                // ...
```

The first `GeneratedMessagePackResolver.GetFormatter<T>()` for any `T` runs the static constructor of
`FormatterCache<T>`, which calls `GeneratedMessagePackResolverGetFormatterHelper.GetFormatter(typeof(T))`. That first call
does both of these:

- The helper's static constructor evaluates `typeof(X)` for every registration, so IL2CPP creates the runtime class of
  every registered type, including every generic instantiation such as `List<Msg0100>`.
- IL2CPP initializes all the metadata a method references the first time the method runs. `GetFormatter(Type)`
  references every formatter type, so its first call initializes all of them and their generic instantiations, even
  though it creates only one formatter.

The cost is paid once, on the first deserialization of any type from the generated resolver, and IL2CPP keeps that
metadata for the life of the process.

## Layout

```
Assets/Scripts/FirstDeserializeProbe.cs   the measurement
Assets/Scripts/Ping.cs                    the type that is deserialized
Assets/Scripts/Messages.g.cs              generated message catalog (Tools/generate_messages.py)
Assets/Editor/BuildPlayer.cs              Repro > Build IL2CPP Player
Tools/generate_messages.py                generates Assets/Scripts/Messages.g.cs
Assets/packages.config, NuGet.config      NuGetForUnity: MessagePack 3.1.12 and its dependencies
Assets/Packages/                          the packages NuGetForUnity installed (see below)
Packages/manifest.json                    NuGetForUnity 4.5.0 and MessagePack.Unity #v3.1.12 git packages
```

`Assets/Packages` is included on purpose. `MessagePack.Unity` does not compile without `MessagePack.dll`, and while
there are compile errors on first open, Unity never runs NuGetForUnity's automatic restore.
