# Nerdbank.MessagePack first-deserialize memory test (Unity IL2CPP)

This branch is the test from `main`, migrated from MessagePack-CSharp 3.1.12 to
[Nerdbank.MessagePack](https://github.com/AArnott/Nerdbank.MessagePack) 1.4.104, the latest stable release, to compare
what the first deserialization costs on IL2CPP. The message catalog has the same types and members; they are marked
`[GenerateShape]` (PolyType) instead of `[MessagePackObject]`.

- Unity 2022.3.57f1, IL2CPP
- Nerdbank.MessagePack 1.4.104 and PolyType 1.4.1 from NuGet through
  [NuGetForUnity](https://github.com/GlitchEnzo/NuGetForUnity) 4.5.0, as Nerdbank.MessagePack's Unity documentation
  describes

## Run it

Unity needs `git` to fetch NuGetForUnity, and the IL2CPP module for the editor's platform (on Windows, also Visual
Studio's C++ build tools).

1. Open the project with Unity 2022.3.57f1.
2. Choose **Repro > Build IL2CPP Player**. This builds a standalone player for the editor's platform into `Build/`.
   **File > Build And Run** works too, because the project already uses IL2CPP and has the scene in its build list.
3. Run the player. The results appear on screen and in the player log (`Player.log`). Pass `-quitAfterProbe` to exit
   when it is done, for example:

   ```
   Build/StandaloneOSX/MessagePackIl2CppRepro.app/Contents/MacOS/MessagePackIl2CppRepro -batchmode -nographics -quitAfterProbe -logFile -
   ```

The numbers only mean something in an IL2CPP player. In the editor (Mono), the IL2CPP counters read 0.

## What it does

[`Assets/Scripts/FirstDeserializeProbe.cs`](Assets/Scripts/FirstDeserializeProbe.cs) runs once after the scene loads.
It takes a snapshot of the memory and IL2CPP counters before and after each of four calls:

1. `serializer.Deserialize<WarmUpMessage>(new byte[] { 0x91, 0x01 })`.
   [`WarmUpMessage`](Assets/WarmUp/WarmUpMessage.cs) is in its own assembly (`Assets/WarmUp`), so this warms up the
   serializer without touching the shapes generated for `Assembly-CSharp`, which holds the catalog and `Ping`.
2. `TypeShapeResolver.ResolveDynamicOrThrow<Ping>()`. This is the shape lookup that `Deserialize<Ping>` starts with.
3. `serializer.Deserialize<Ping>(new byte[] { 0x91, 0x01 })`. [`Ping`](Assets/Scripts/Ping.cs) is a class with one
   `int` field.
4. The same call again.

It also prints steps 2 and 3 combined, which is what the first `Deserialize<Ping>` costs.

[`Assets/Scripts/Messages.g.cs`](Assets/Scripts/Messages.g.cs) stands in for a game's message catalog: 600 classes,
60 structs and 80 enums, whose members use `List<T>`, `T[]`, `Dictionary<K, V>` and so on. The probe never uses these
types. It was generated by [`Tools/generate_messages.py`](Tools/generate_messages.py), with the same seed as on `main`.

"Native memory" is `Profiler.GetTotalAllocatedMemoryLong()`; IL2CPP allocates its runtime metadata through Unity's
memory manager, so it is included. The IL2CPP columns come from `il2cpp_stats_get_value`.

## Results

macOS 27 standalone player on Apple silicon; the numbers were identical in every run:

| Step | Native memory | Managed heap | Classes initialized | Methods | Generic classes | Inflated methods |
|---|---:|---:|---:|---:|---:|---:|
| 1. `Deserialize<WarmUpMessage>`, warm-up | 1,409 KB | 108 KB | 431 | 2,977 | 693 | 3,765 |
| 2. `TypeShapeResolver.ResolveDynamicOrThrow<Ping>()` | 154 KB | 20 KB | 9 | 41 | 4 | 45 |
| 3. `Deserialize<Ping>` #1 | **3,644 KB** | 200 KB | **44** | 410 | 134 | 547 |
| 4. `Deserialize<Ping>` #2 | 0 | 0 | 0 | 0 | 0 | 0 |
| First use of `Ping` (2 + 3) | 3,798 KB | 220 KB | 53 | 451 | 138 | 592 |

Compared with MessagePack-CSharp 3.1.12 on `main`, with the same catalog:

| First use of `Ping` | Native memory | Classes initialized | Inflated methods |
|---|---:|---:|---:|
| MessagePack-CSharp 3.1.12 | 11,077 KB | 5,755 | 26,029 |
| Nerdbank.MessagePack 1.4.104 | 3,798 KB | 53 | 592 |

Nerdbank.MessagePack initializes only the classes `Ping` needs, but its first deserialization still costs more with a
larger catalog. With a catalog one-tenth the size (67 shaped types), the first use of `Ping` costs 642 KB; with the
default (661 shaped types), 3,798 KB. The class and method counts are the same in both.

What allocates those 3.6 MB has not been identified. Two things were ruled out:

- **Class initialization:** the IL2CPP counters do not change with the catalog size.
- **The generated provider's `GetTypeShape(Type)`:** it switches on `type.ToString()` over all 2,152 types it has shapes
  for (the catalog types plus their collection types), and IL2CPP initializes those 2,152 string literals the first
  time it runs. Calling it directly costs 0 KB of native
  memory and 248 KB of managed heap, and `Deserialize<Ping>` does not call it.


## Deserializing every message (`-allMessages`)

With `-allMessages`, the probe then deserializes every catalog class (`Msg0000` to `Msg0599`) and struct (`Pod000` to
`Pod059`) once, in that order, and then all of them again. [`Tools/generate_all_messages.py`](Tools/generate_all_messages.py)
writes their payloads to `Assets/Scripts/AllMessages.g.cs`: primitives, enums and structs filled in; references,
collections and nullables nil, as MessagePack-CSharp writes `[Key]` types. Run it after `generate_messages.py` if the
catalog changes.

```
Build/StandaloneOSX/MessagePackIl2CppRepro.app/Contents/MacOS/MessagePackIl2CppRepro -batchmode -nographics -quitAfterProbe -allMessages -logFile -
```

Same player, after steps 1 to 4; identical in three runs except the time (±2%):

| Step | Native memory | Managed heap | Classes initialized | Methods | Generic classes | Inflated methods | Time |
|---|---:|---:|---:|---:|---:|---:|---:|
| 5. `Msg0000` | 140,040 KB | 5,844 KB | 36,043 | 347,889 | 83,946 | 422,380 | 386 ms |
| 6. `Msg0001`–`Msg0009` | 107,724 KB | 4,368 KB | 27,399 | 267,013 | 64,853 | 323,312 | 340 ms |
| 7. `Msg0010`–`Msg0099` | 113,235 KB | 5,692 KB | 29,657 | 283,568 | 67,413 | 343,731 | 490 ms |
| 8. `Msg0100`–`Msg0599` | 8,621 KB | 0 | 4,122 | 17,054 | 4,862 | 27,062 | 37 ms |
| 9. `Pod000`–`Pod059` | 256 KB | 56 KB | 300 | 300 | 180 | 1,140 | 1 ms |
| 10. All 660 again | 0 | 80 KB | 0 | 0 | 0 | 0 | 2 ms |
| **All 660, first time (5–9)** | **369,876 KB** | 15,948 KB | 97,521 | 915,824 | 221,254 | 1,117,625 | **1,254 ms** |

Building a converter builds converters for every type it can reach, so the cost lands on the first message of each part
of the graph: `Msg0000` alone reaches much of the catalog, and the first 100 messages (the catalog's top layer) reach
nearly all of it, which leaves little for the other 500. Together with steps 1 to 3, the whole catalog costs about 375 MB
of native memory. The `messagepack-all-messages` branch measures the same with MessagePack-CSharp 3.1.12:
28,498 KB and 76 ms for steps 5 to 9, about 41 MB in all.

## NativeAOT (`NativeAot/`)

[`NativeAot/`](NativeAot) is the probe as a .NET 10 console app: it compiles `Assets/Scripts/Messages.g.cs`, `Ping.cs` and
`AllMessages.g.cs` and runs the same steps under NativeAOT. It needs the .NET 10 SDK, and reads the process footprint with
`proc_pid_rusage`, so it runs on macOS:

```
dotnet publish NativeAot -c Release -r osx-arm64 -o NativeAot/out
NativeAot/out/MessagePackIl2CppRepro.NativeAot
```

`dotnet build NativeAot -c Release -o NativeAot/out-jit` builds the same app for the JIT runtime. It differs from the Unity
probe in that `Ping`'s shape comes from `IShapeable<Ping>.GetTypeShape()`, the source-generated path on .NET,
instead of `TypeShapeResolver.ResolveDynamicOrThrow<Ping>()`; `NativeAot/WarmUp/` builds `Assets/WarmUp` as its own assembly, every step is timed, and it reports the process footprint, the managed heap and the managed bytes
allocated per step, then what is still held after a full GC and the peak footprint.
[REPORT.md](https://github.com/AlanLiu90/MessagePackIl2CppRepro/blob/main/REPORT.md) on `main` has the results.

## Layout

```
Assets/Scripts/FirstDeserializeProbe.cs   the measurement
Assets/Scripts/Ping.cs                    the type that is deserialized
Assets/Scripts/Messages.g.cs              generated message catalog (Tools/generate_messages.py)
Assets/Scripts/AllMessages.g.cs           a payload and Deserialize call per catalog type, for -allMessages
Assets/WarmUp/                            WarmUpMessage, in its own assembly (Repro.WarmUp.asmdef)
Assets/Editor/BuildPlayer.cs              Repro > Build IL2CPP Player
Assets/packages.config, NuGet.config      NuGetForUnity: Nerdbank.MessagePack 1.4.104 and its dependencies
Assets/Packages/                          the packages NuGetForUnity installed (see below)
Packages/manifest.json                    NuGetForUnity 4.5.0 git package
Tools/generate_messages.py                generates Assets/Scripts/Messages.g.cs
Tools/generate_all_messages.py            generates Assets/Scripts/AllMessages.g.cs
NativeAot/                                the probe as a .NET 10 NativeAOT console app
```

`Assets/Packages` is included on purpose: the scripts do not compile without it, and while there are compile errors on
first open, Unity never runs NuGetForUnity's automatic restore.
